# AI 对话与练题流式链路修复计划

目标：修复错误终态、断流伪成功、重复重试及分批失败被吞掉的问题，保持现有页面和 API 路径。
范围：客户端 SSE 传输、服务端普通与分批 SSE、模型降级配置及相关测试；不改题库、考试和评分业务。

- [x] 用实际 SSE 帧复现 CRLF、末帧、断流和终态重复问题，运行失败测试。
- [x] 抽取客户端 SSE 状态机：终态唯一、取消可中断等待、超时可见、断流失败。
- [x] 用本地 HTTP 上游模拟器测试服务端：429 恢复/耗尽、鉴权/额度、空流、断流、部分输出失败、取消。
- [x] 抽取普通/分批共用上游传输；统一有界重试，尊重 Retry-After，禁用未知模型的硬编码降级。
- [x] 普通/分批共用 SSE 生命周期：排队期间心跳、连接中断取消、失败不伪装完成；分批验证题目数组。
- [x] 运行前后端测试、构建和差异检查，记录无法验证的真实上游条件。

验证：npm test；mvn -s .mvn/settings.xml -f backend/pom.xml test；npm run build:web。
真实账号额度或供应商拥塞不能通过本地代码保证消除；不使用真实密钥执行付费测试。


## 实施结果与验证

- 客户端传输抽取到 `src/api/aiStream.ts`，保留既有 API 函数、认证头和进度回调。终态唯一，CRLF/跨包/EOF 末帧正确解析，断流不再补造成功，等待重试可取消，心跳超时可见。
- 上游 HTTP/SSE 抽取到 `AiStreamClient`：最多 3 次尝试，尊重 Retry-After；鉴权/额度不足不重试，已经输出内容后不重放；正常结束标记和 finish_reason 均受校验。真实 HTTP 模拟器验证活动连接与退避等待均可取消。
- 普通与分批流共用请求、排队、心跳、取消、终态和统计。慢连接心跳隔离；取消通过可中断的虚拟线程终止阻塞 I/O，避免调用 disconnect 本身阻塞请求方。
- 练题输出复用既有 AiQuestionPolicy 验证，并验证数量；任何批次失败都不能上报整体成功。续出题目使用本次要求的数量。
- 熔断探测在输入校验/限流/排队之后申请；取消不记为上游失败，可释放恢复探测位。修正 OPEN 转 HALF_OPEN 后首个请求未占用探测位而导致两个探测并发的问题。
- 流式请求严格使用 AI_MODEL，不再悄悄改成硬编码模型。支持通过 AI_API_URL 指定上游地址；未改考试、题库、评分的业务行为。
