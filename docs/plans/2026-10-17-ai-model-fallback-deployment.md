# AI 主备模型与部署计划

需求：glm-4.7-flash 优先；失败时自动降级 glm-4-flash；验证后推送并部署现有服务器。
证据：服务器最小请求探测中，4.7 返回 HTTP 429 / 1305；4-flash 返回 HTTP 200。部署前服务为 88a132f，模型环境为 glm-4-flash。

- [x] 测试先行：主模型繁忙/空响应切换备用；鉴权/权限错误不切换；部分输出不重放；总尝试次数有界。
- [x] 在共用流式客户端加入请求内主备切换，配置 AI_MODEL、AI_FALLBACK_MODEL，保留取消与 Retry-After 约束。
- [x] 运行前后端测试与生产构建，审阅差异；不提交私钥、配置密钥和环境文件。
- [ ] 提交并推送 master。备份服务器配置与现有 JAR/前端，更新模型环境，运行既有更新流程。
- [ ] 确认远端提交、服务健康、部署版本、实际主备请求结果；失败时保留证据并恢复可用版本。

限制：不修改数据库模式或业务数据；不重置未知远端业务源码。生成静态资源允许由现有部署脚本重建；未追踪的服务器密钥/环境文件不得被删除或提交。


实现：AI_MODEL 默认 glm-4.7-flash，AI_FALLBACK_MODEL 默认 glm-4-flash。主模型 HTTP 429/5xx/模型不存在、无输出的空流或连接失败可降级；401/403/账户额度不足不盲目切换；已有输出后失败不重放；最多 3 次上游尝试。GLM-4-flash 备用请求不携带 thinking 字段。同步调用也修正了“切换变量却未刷新请求体”的问题。

部署前验证：后端 683 项、前端 136 项通过；秘密卫生检查 8 项通过；生产前端构建通过（仅大包体警告）。独立只读审阅无重要发现。完整类型检查在先前已记录的 4 个未修改文件中失败，未混入本次修复。
