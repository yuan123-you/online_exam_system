# 考试发布版本：部署与历史数据边界

本文件记录新增的考试快照方案，不代表已执行部署或线上迁移。

## 生效规则

- 首次发布事务：锁定考试、试卷和引用题目，读取数据库最新数据，保存考试和独立快照。任一步失败均回滚。
- 冻结内容：试卷名称、题目顺序、答题时长、总分、及格分，以及题干、选项、答案、分值和题目相关元数据。
- 草稿预览使用当前题库；已产生快照的考试撤回后也保留首次版本，再次发布不重建。需要不同内容时创建新的考试。
- 不冻结考试日程和目标班级。本阶段没有改变原有排期、手动延时或班级权限规则。
- 发布会拒绝缺失/重复引用、跨教师题目、非正分值、题目分值合计与试卷总分不一致，避免发布不完整的版本。
- 学生取题隐藏标准答案，独立快照不会嵌入考试列表/初始化响应。
- 新表中的原始版本只由后端生成，客户端传入的 snapshot 字段不能成为版本来源。

## 数据结构及迁移

新增 `exam_snapshot`：`exam_id` 主键且外键关联 `exam`，`content_json` 为 JSON，`created_at` 记录捕获时间。每场考试至多一条发布版本；应用没有覆盖快照内容的 UPDATE 或 UPSERT 路径。

独立迁移文件：`D:\Codex Web\online_system\db\migrations\2026-10-08-exam-snapshot.sql`。

`schema.sql` 同时包含相同的 CREATE TABLE IF NOT EXISTS，用于现有初始化方式；未改用另一套迁移框架。此次编程没有连接实际 MySQL，没有执行上述 SQL。

## 上线前必须完成

1. 备份原有考试、提交详情及题库/试卷，检查恢复能力。
2. 在隔离 MySQL 8 环境应用新增 DDL，验证实际存储格式、锁行为及并发发布。当前事务集成测试使用 H2 MySQL 模式，不能代替目标 MySQL 验证。
3. 盘点已发布但缺少快照的考试（包括初始化种子考试），不得直接在有考试进行中的环境切换新版本。
4. 对每场历史考试确认是否存在可信的发布时原始试卷/题目备份。只有可验证来源才能恢复原始快照；恢复工具/审批流程未在本阶段实现。
5. 运行备份数据的兼容性测试、全量后端测试及隔离账号验收；现有基线失败仍需修复，不能因本功能测试通过就直接上线。

只读盘点 SQL（不会生成快照）：

```sql
SELECT e.id, e.name, e.published
FROM exam e
LEFT JOIN exam_snapshot s ON s.exam_id = e.id
WHERE e.deleted = 0 AND e.published = 1 AND s.exam_id IS NULL;
```

## 缺少历史版本时的行为

- 列表/已有成绩显示 `contentVersionStatus=MISSING`，已保存的 finalScore 和 answerDetail 不被重算或改写。
- 不使用当前试卷冒充历史总分/及格标准；成绩审查和 Excel 导出显示版本待恢复，不因缺失及格线而将成绩标为通过。
- 获取题目、新建/继续答题、班级分析及重新自动评分（含 AI 评分建议）返回明确冲突错误（HTTP 409），禁止使用当前题库替代。
- 编辑已发布且缺少原始版本的考试也拒绝自动回填。已撤回但存在学生提交记录的历史考试同样视为版本缺失，不能重新冻结当前题库。不能通过撤回再发布将未知历史伪装成原始版本。
- 旧数据中“曾发布又撤回、且没有任何提交记录”的情况无法仅凭当前字段识别；上线盘点必须人工核对发布历史，不能把状态为未发布当成历史原版可恢复的证据。
- 未实现根据当前题库强行补齐、自动改写历史成绩或恢复工具。历史修复策略需要确认真实来源后单独实施。

## 回滚约束

回滚应用时保留 exam_snapshot 表和原始记录，不能删除版本或重新生成。旧应用并不保证版本冻结规则，因此不能将“切回旧应用”视为无损业务回滚，尤其不能在考试进行中未经评估切换。迁移本身是新增表，没有修改已有成绩。

## 本阶段未覆盖

- 真实 MySQL 环境的集成验收，以及历史快照恢复。
- 所有旧测试基线失败和整个项目全面重构。
- 错题本当前题库再练习的版本策略（现有路径有跟随当前题库的行为，需单独明确题目版本与练习规则）。
- 其他两个项目的交易/内容状态重构。
